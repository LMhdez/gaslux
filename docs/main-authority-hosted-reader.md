# Hosted Safety reader integration

Safety approved the authenticated live protected-ref ledger read as conditional replacement for the SSH nonce query (7222608267). HostedClient uses a dedicated control repository read credential and pinned Safety public key, validates full signed chain and stable authenticated ref through Ledger.snapshot, bounds elapsed time, checks exact evidence and decision signature, and does not cache approval. The publisher uses the hosted feed and scoped publisher witness only when selected in a frozen reviewed deployment; the original SSH path remains explicit. The production backend selector remains null. New pins and real credential scopes still need provision. A 15-second elapsed guard rejects slow results; it is not a hard network cancellation deadline. No actual live credentials or status writes.

## Authority boundary requiring explicit Safety decision
A Pi holding BOTH the production status-writing App key and a main merge-capable credential can bypass its own local journal after host compromise. Protected ledger reads and local mutexes do not prevent arbitrary API calls by root holding those credentials. Native review remains enforced today, but replacing it with only a status that the Pi can issue would undermine the accepted threat model. Recommend retaining Pi as scheduler/orchestrator and moving the final authority-bearing status and merge credential to a frozen hosted workflow (separate identity/credential from signer; no candidate code, no Pi key copy), or require a separate hosted independent gate that the Pi cannot write plus a server-enforced exclusive merge path. This is a proposed adjustment to authority placement, not a unilateral change. Do not enable merge until independently reviewed and operationally verified.
