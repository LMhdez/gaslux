# GASLUX — Isolated parent boundary admission

This is a **synthetic fixed-client admission test**, not evidence of an isolated OpenCode binary, real model inference, product editing or operational authority. It reuses the pathless MCP broker, 259-case oracle and journal verifier. A distinct host controller starts the broker outside the client's user/mount/PID/network/IPC/UTS namespaces. The client receives only a writable scratch directory, read-only system runtime, virtual proc/dev, private tmpfs, and one bound Unix socket; neither broker state, control, repository nor host HOME is mounted.

The fixed client observes RED, rejects arbitrary tool/path and stale SHA, then edits and tests to PASS. It attempts read/write of real host journal, seed, task and sentinel (including via /proc/1/root), exclusive forgery and host-local TCP. Host verifies exact journal and independently reruns the candidate. Only synthetic results; all writer/merge/release flags false.

The existing job installs distro-signed bubblewrap if absent, then runs as the ordinary non-root runner. Unsupported user namespaces/AppArmor policy or missing isolation fail the admission; no sysctl/AppArmor relaxation, root execution or non-isolated fallback. The prior OpenCode trial remains a separate synthetic experiment. The new test is **not yet a substitute** for the real OpenCode pilot: connect the real binary to a separately bounded model-only proxy inside the private network namespace (no arbitrary host Ollama API, external network, or host sockets), measure resource limits, then run real native skills and MCP RED→PASS. Independently review the complete confinement before enabling operational consumption. The current check is a prerequisite, not operational authorization.

### Fecho do contrato de desenvolvimento antes de Safety

O shadow exige Ruff lint/format do módulo composto, o mesmo factory.verify (execute=False, relatório/bytes temporários no controlador e SHA do relatório verificado; nenhum artefacto publicável exportado), e regressões antes/depois. O contexto do produto só admite campos fixos; role selecionável nas opções do dispatch experimental, ausência de helper exigida. Se o helper já existir, recusa o replay. Todos os seis contratos têm teste funcional offline, não seis inferências reais. O worker fecha descritores herdados (preserva só pipe de resultado); proxy valida também nomes e argumentos JSON de tool_calls históricos e IDs de resposta vinculados. Não amplia escopo nem permissões. Os controlos de estilo podem rejeitar uma edição final e ainda não existe reparação Ruff/pytest dentro do modelo para este shadow; o ciclo MCP corrige apenas AST e testes funcionais. Pipeline produtivo continua separado e desativado para OpenCode até revisão e admissão de âmbito real. A validação Safety independente é deliberadamente posterior à conclusão deste desenvolvimento, conforme pedido.
