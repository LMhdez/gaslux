# Hosted Safety and Pi deployment — staged implementation

Decision: Safety 7222498663 accepts trusted GitHub administrator model; compromised agents/Pi must not access Safety signing key, control-repo write, or administration. 91 tests confirmed at b9e41fa68cd99a2cdceb75b91e7f52f5cafd0076 (run 46027943932).

## Separate repository scopes (required, not provisioned)
Use a private Safety control repository containing frozen workflow/code and protected ledger/safety branch, and a separate private publisher checkpoint repository. The signer ledger itself is the persistent witnessed authority: signed append-only events, exact pinned genesis, protected deletion/non-FF no bypass. No ephemeral SQLite or Actions artifacts are used as signer authority in this design. Pi gets only control-repository Contents read + Administration read (for policy inventory); no control repo writes. Its publisher witness credential is scoped only to its own separate repository. Hosted signer must not possess publisher write. Use fine-grained permissions and explicit negative server-side tests. Do not put both write tokens in the same repo; do not copy admin tokens to Pi. Current optional same-repo GitWitness adapter is NOT suitable without server-enforced role isolation; a separately scoped publisher-only variant still needs implementation. Control repo workflow ref must be frozen by its own exact no-bypass rule; environment restricted to that exact ref; GitHub-hosted runner only, no candidate checkout. A trusted GitHub administrator may provision these resources once, with independent admin recovery before retiring Pi admin credentials.
