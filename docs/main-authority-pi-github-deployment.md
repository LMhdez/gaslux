# Pi + GitHub alternative: staged, no production authority

## Decision required from independent Safety
Available infrastructure: Raspberry Pi and GitHub only. Proposed trust boundary:
- Pi: scheduler, publisher and eventual dedicated merge service. It is not the Safety key custodian.
- Separate private GitHub Safety control repository: immutable protected workflow, GitHub-hosted runner only, isolated environment and signer key. No candidate code execution or checkout in a secret-bearing job. Persistent signer ledger must be append-only and protected; runner disk/artifacts are not authoritative storage.
- Separate private GitHub witness repository: two fixed append-only ledger branches, role-separated scoped credentials, protected against deletion and non-fast-forward updates. This is separate from both local DB snapshots and the Safety control repository.

A common account owner can change rules/secrets and is a common administrative trust root. This architecture does NOT satisfy the earlier requirement of independent administrators against a malicious/compromised common owner. Safety must explicitly approve a narrower threat model (compromised autonomous agent or Pi service, but trusted GitHub account administrator) OR require a one-time independently administered repository/account. No recurring human approval assumption. If neither is accepted, keep native review and pause; do not claim autonomous authority. Existing admin gh credentials on the Pi are incompatible with independence from Pi-root compromise; remove/revoke them from operational host after one-time provisioning using an admin-controlled session, leaving only fine-grained role credentials. Do not revoke current access until alternative admin recovery has been verified.

## Implemented optional GitHub witness
github_witness.py uses exact private repo ID, exact protected ruleset ID, exact role branches and pinned genesis commits. Each event is a single canonical JSON blob in a one-parent commit, validated against full pinned ancestry, role, sequence, previous digest, uniqueness and current ref. Non-fast-forward/delete prohibited with empty bypass inventory; missing inventory denies. The API updates only by force=false, verifies live tip before and after and never retries ambiguous writes. Bound 256 events per role; stop rather than reset if exhausted. Provisioning is separate and must be reviewed, including private-repo ruleset availability, repo/role permissions and admin/read visibility. Both pins and optional backend selection are intentionally inactive. This does not protect against an authorized administrator disabling rules or rewriting the trust root, nor against a malicious checkpoint writer corrupting future state (denial of service).

## Hosted Safety work still required
Do not run the current SSH worker unmodified on ephemeral Actions. GitHub-hosted runners cannot provide an always-on SSH server; the current 15-second nonce query contract cannot be guaranteed by workflow dispatch. Before production, design an independently witnessed append-only signer ledger with protected hosted evaluator workflow, authenticated current-state read and retained signed decisions. A live-ref authenticated read of a signed current-state record could replace nonce query only with explicit Safety approval and new tests; don't silently relax query freshness. A separate exact merge adapter must still serialize decisions with actual merge and deny on unresolved status. GitHub-hosted Actions and Git history do not prove administrative independence by themselves.

No new Apps, repos, PRs, rules, secrets or production writes have been created by this implementation. Existing native gates, all production pause flags and prior technical decisions retained. Request Safety review of adapted trust model before user spends time provisioning new repositories.
