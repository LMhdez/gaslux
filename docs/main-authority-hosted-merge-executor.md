# Hosted main merge executor (staged)

Safety decision 7222719643 approves keeping final status and merge keys off the Pi. The new github_main_merge.py implements a real fixed GitHub PUT /repos/LMhdez/gaslux/pulls/{allowlisted PR}/merge with exact head SHA and merge method merge, separate main-only App registration and installation scope, exact pinned policy inventory, effective exclusive update-only ruleset with PR-only App bypass (native review and additive source-pinned gate retained), no redirects and no retry. Dedicated identity pins are null; not authorized for production. Do not repurpose the status App or existing dev merge App. Real merge receipt requires exact PR merged_by identity, exact parents/tree and live main ancestry/readback; matching tree alone is insufficient.

hosted_merge_executor.py serializes operation under shared journal lease, verifies the full signed decision feed and complete durable publisher journal/actual status history, checks exact independent CI/evidence and policy before reservation and dispatch, records signed posting intent, revalidates live signed tip immediately before PUT, and reconciles only exact authenticated receipt. Withdrawal before dispatch or changed tip denies dispatch; after posting, an unresolved request remains blocked indefinitely until exact receipt (no timeout or blind retry). A restarted reserved-but-not-posted operation can be aborted only under sole controller ownership. A late merge after signed withdrawal is an incident in the signed ledger. Ten new offline tests use mock transport and ephemeral keys; no real PUT performed.

## Deployment constraint and next work
This is a callable real transport/executor, NOT an active workflow. It requires a **durable hosted publisher journal reconstructed and independently checkpointed before every run**, not ephemeral SQLite or runner artifacts. The existing Pi journal path is not appropriate for final authority. Sole protected controller must be the only ledger writer and merge dispatcher; same concurrency group, exact workflow/environment/ref pins, no competing signing or revocation workflows, no Pi-held keys/admin. Pending workflow replacement is not durable decision delivery. Need implement durable hosted publisher storage/reconstruction and authenticated retained revocation input, integrate controller with hosted evaluator, validate key custody and real server-side negative/positive cases. Existing workflow template is not yet the sole controller.
