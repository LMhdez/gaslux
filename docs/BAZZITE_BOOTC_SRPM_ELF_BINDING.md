mounts, ESP writes, partitions, NVRAM, boot, or Windows recovery. Draft stacked

## ESP threat matrix (conditional source analysis)

| Target and mode | Real upstream Rust behavior | Decision |
| --- | --- | --- |
| Windows ESP, `replace=alongside` | `clean_boot_directories` calls `clean_esp_bootloader_dirs` -> removes `EFI` and `loader` dirs on selected ESP | **DENY** — potential deletion of Windows EFI |
| Dedicated Linux ESP, `replace=alongside` | Same recursive cleanup; ESP mounted destination and ownership not independently bound | **DENY** |
| Any root, `replace=wipe` | `remove_all_in_dir_no_xdev` removes root contents | **DENY** |
| Dedicated Linux ESP, `replace=none` | `ostree admin init-fs`/deployment, then bootupd or bootctl: EFI/NVRAM write-set unproved | **DENY** |
| Windows ESP, `replace=none` | Bootloader may install EFI files/entries to selected ESP despite no cleanup | **DENY** |
| BIOS/MBR | Bazzite Gaslux permits UEFI/GPT only | **DENY** |
| Foreign disk, transaction, bootloader or incomplete plan | Existing real `assess_candidate` requires exact GUID, ESP and transaction and refuses destructive modes | **DENY** |

The native `bootc install to-filesystem` is not executed. It requires
externally prepared/mounted partitions; the source demonstrates neither an
authorized GPT write-set nor an authorization of NVRAM changes. A separate
Linux ESP is necessary as a design isolation boundary, but **not sufficient**
to demonstrate preservation of Windows Boot Manager.

## Implemented invariant and validation

`auto_tests/bazzite_bootc_srpm_elf_gate.py` composes the **existing**
`bazzite_bootc_prewrite_source.assess_candidate` gate, checks exact
source RPM/OCI ELF/build-id/F45 key/source identities, and denies
any mismatched RPM/source digest, unknown patch, Windows ESP, foreign disk,
BIOS/MBR, `replace=alongside`/`wipe`, bootloader/transaction mismatch and
partial plan. A structurally consistent self-authored evidence object can
**never** claim `SOURCE_ELF_BOUND`, installation authority, ESP authority
or a verified rollback.

`.github/workflows/bazzite-bootc-srpm-elf-deny.yml` has an offline
negative-contract job and an isolated Fedora SRPM inspection job: download
the actual official SRPM and Fedora certificate, check **the published Fedora
45 fingerprint**, verify the SRPM via an isolated RPM DB, inspect actual
NEVRA/spec/source entries without running RPM scriptlets, compare two Rust
source files against immutable Git tree, emit hashes and a deny-only verdict.
The source probe must fail if an upstream digest, signature, patch, or
layout mismatches; it never downloads/executes bootc and does not retain
the SRPM binaries. The result of that job must be assessed from its exact
HEAD GitHub Actions logs; workflow definition itself proves nothing.

**Final verdict for permission:** `SOURCE_ELF_UNPROVEN` /
`DENY_NO_WRITER`. Neither the RPM NEVRA nor an SRPM signature implies
a reproducible source-to-ELF build. Even a complete source identity binding
would not prove a safe dual boot or permit installation.
