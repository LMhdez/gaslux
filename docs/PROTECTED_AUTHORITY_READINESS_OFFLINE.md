## Two stages: observation versus authority

The diagnostic schema `schemas/protected-authority-readiness-v1.schema.json` accepts **untrusted** read-only observations only. It explicitly rejects unexpected fields such as `authorized: true` at the top level or `trusted: true` in a probe. Individual controls have three *defined* categories:

| Status | Meaning | Emitted by this offline module? |
|---|---|---|
| `VERIFIED` | Proven by independently authenticated and authorized administrative source | **No**; requires a future externally reviewed adapter and trusted transport |
| `MISSING` | Proven absent by comprehensive authorized inspection of all relevant controls | **No**; GitHub read-only response alone cannot establish full administrative completeness |
| `NOT_VERIFIABLE` | Absent, untrusted, unauthorized, inaccessible, incomplete, conflicting or not independently authenticated | **Yes** |
| Global `BLOCKED_TRUST_ROOT` | One or more critical controls cannot be proven; no operational permission | **Always** |

An HTTP 200, a matching SHA, GitHub event, unauthenticated JSON, runner-local signed message, OIDC or HMAC generated by the runner, self-reported `GITHUB_READ_ONLY` source label, screenshot, green CI or PR approval comment cannot create the missing administrative trust root. This component does not perform API calls or accept external credentials. It records **reasons only** from untrusted evidence. A later independent verification service cannot be replaced by fixtures or merely turning a boolean to true.

## Separation of required actors

| Actor | Required independence and responsibilities | Real state |
|---|---|---|
| Authority A — execution | Separately administered human decision, reviewed exact preparation/authorization/controller/code SHA, protected branch + required human reviewer, enforce requester/approver separation and revocation | **Not operationally demonstrated** |
| Authority B — evidence | Independently verified VM guest, backing chain, QEMU process/FD, time/nonce and measured bytes; authentic collection chain | **Not implemented as an authority** |
| Protected controller | Lives on reviewed protected main branch; reads out-of-band approved pins, never executes feature-branch scripts before checks, consumes external lease before any allowed guest launch | **Template in #275 is inert** |
| External ledger | Durable uniqueness (global commit and decision), linearizable atomic once-ever consumption, independent revocation and snapshot rollback resistance, ACL outside runner/branch | **#285 SQLite is a disposable model only** |
| Coordinator | Authenticated plan, Windows/system disk, transaction, VM, backing identity, single-use fresh challenge, independent clock, exact code checkout | **Not independently established** |
| Safety no-writer | Reject unsupported/ambiguous writes; `ACCEPT_NO_WRITER` does not authorize disk writes | **#267 experimental denial-only** |
| HOST observer | Supplies local diagnostics for later independent correlation, without declaring origin authenticity | **#294 diagnostic only** |

An Authority A approval never proves Authority B's guest observation. A valid signed payload still does not prove physical byte provenance. The caller cannot manufacture external reviewer identity by choosing fields inside JSON.

## Failures and adversarial coverage

- Missing/403 rulesets/protection/environments; lack of reviewer policy; self-approval; wrong controller ref/branch; mismatched prepared/authorized SHA; recreated branches; stale/reused challenge; inadequate token permissions.
- Synthetic PR comments and green CI; all 23 control responses self-proclaimed by runner; structural 200s with `verified:true`; unknown schema fields attempting to enable `authorized`; SQLite local or restored snapshot.
- Exact #275 `validate_git` refusal with missing trusted pins; #285 v2 schema, global commit/decision identities, replay/recreation refusal; #267 genuine `decide_no_writer` refusal with untrusted inputs.
- No secret, key, certificate, GitHub admin mutation or real VM is created.

The single use model cannot authenticate its caller or resist rollback of the runner-local database. A successful #285 unit test only proves SQLite's local transactional semantics. `MISSING` and `VERIFIED` states must be implemented only after an independent administrator-controlled evidence adapter exists; this PR **must not** expand its own permissions to support them.

## Remaining mandatory acceptance controls

1. Human administrator inspects and exports verifiable ruleset/branch protection/review policy and Environment settings from an independently controlled identity; verify scope, inheritances, requester restrictions and required reviewers.
2. Establish protected/controller source SHA integrity and token-scoped execution identity under external administration.
3. Design a durable externally hosted once-ever ledger with immutable global commit keys, revocation, trusted time and failure/rollback semantics; independently audit.
4. Establish independent guest/VM/Windows measurement sources and a coordinator challenge binding.
5. Re-audit Safety and human responsibility under `AI_POLICY.md`; no merge, no enabling a controller or QEMU on acceptance of this diagnostic alone.
